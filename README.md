# model-training-lab

A collection of reproducible experiments for understanding model training, data, optimization, and evaluation from first principles.

通过提出问题、实现方法、记录结果和分析失败，理解模型训练、数据、优化与评测。仓库保存实验的可复现过程；形成完整研究或工程项目后，再按需要拆分为独立仓库。

当前阶段：首个实验已完成数据观察和 Tiny ViT forward，正在学习 patch、token、CLS 与 logits。尚未更新模型参数或取得训练指标。

## 仓库组织

后续实验使用 `<编号>-<主题>/`，例如 `01-example/`。下面展示的是约定，不代表这些实验已经创建。

```text
model-training-lab/
├── README.md
├── AGENTS.md
├── .gitignore
└── <编号>-<主题>/
    ├── README.md              # 问题、实验设置、结果与分析
    ├── src/                  # 实现
    ├── configs/              # 可复现的实验配置
    ├── scripts/              # 训练、评测和结果整理入口
    ├── results/              # 精选图表、指标摘要和对比表
    └── notes/                # 推导、调试过程、失败尝试与复盘
```

共享代码在出现真实复用需求时再提取；不预先创建未确定的模型或实验项目。

## 本地环境与实验资产

本机硬件清单、账号信息、代理和环境初始化脚本仅保存在本地，不随 Git 分发。在已配置的服务器上，本地说明入口为 `硬件环境配置信息/README.md`；其他机器需自行配置计算资源和存储位置。

使用 `LAB_ROOT` 表示实验资产根目录。代码和说明保留在仓库，环境、共享模型、数据、完整检查点及运行日志存放在仓库外。每个实验使用独立环境，并在自己的 README 中写出实际安装与运行方法。

| 内容 | 位置约定 | 是否进入 Git |
| --- | --- | --- |
| 实现、配置、依赖清单与锁定文件 | 实验目录 | 是 |
| 问题、假设、推导、失败分析和实验结论 | 实验 README 与 `notes/` | 是 |
| 指标摘要、精选曲线和对比表 | 实验 `results/` | 是 |
| Python/Conda 环境 | `$LAB_ROOT/envs/<项目>/<环境名>/` | 否 |
| 共享模型、原始数据和处理结果 | `$LAB_ROOT/models/`、`$LAB_ROOT/datasets/` | 否 |
| 完整检查点、日志和运行产物 | `$LAB_ROOT/runs/<项目>/<运行标识>/` | 否 |
| 本机硬件、凭据和代理细节 | 本地配置 | 否 |

环境锁定文件不应含私有下载凭据或本机安装前缀。模型和数据版本应使用模型 ID、revision、数据集版本或校验和标识；公开结果避免携带本机绝对路径和设备 UUID。

## 每个实验的记录模板

将以下八部分写入实验自己的 README，并随实验更新：

### 1. 问题 / Question

要回答什么问题？比较对象是什么？用什么指标判断结论？

### 2. 假设 / Hypothesis

预期会发生什么，理由是什么？哪些观察会否定这个假设？

### 3. 实现 / Implementation

模型、数据处理和训练方法；对应代码入口；引用使用的论文、教程或上游实现，说明自行修改的部分。

### 4. 实验设置 / Experiment Setup

- 代码提交 ID，以及是否存在未提交改动；必要时在本地运行目录保存补丁。首次提交前明确标注代码尚未版本化。
- 依赖清单或锁定文件、Python 与训练框架版本，以及可复制的安装和运行命令。
- 数据来源、版本、预处理方法、划分方式与随机种子。
- 模型来源与 revision，优化器、学习率、batch size、梯度累积、精度、训练步数及评测方法。
- 本地记录所用计算资源、设备 UUID、存储位置和运行标识；本仓库当前不公开本机硬件与环境记录。

### 5. 结果 / Results

指标表、精选图表和运行标识；明确区分已测结果与预期。正式比较尽量覆盖多个随机种子，并报告波动及实验预算。

### 6. 分析 / Analysis

结果是否支持假设？哪些因素仍可能影响比较？记录失败尝试、异常现象与证据，不只展示最优一次结果。

### 7. 学到的内容 / What I Learned

本实验澄清了什么概念，发现了什么实现问题，还不能得出哪些结论？

### 8. 下一步 / Next Experiment

由当前结果引出的下一个问题，以及希望控制或改变的变量。

## 从一次运行到可展示结果

1. 写出问题、假设和配置；确定 GPU 与存储位置。
2. 用独立环境进行小规模检查，确认数据划分、loss、评测及产物路径正确。
3. 创建独立运行目录，保存实际命令、配置、环境版本、随机种子和代码状态。
4. 执行实验并记录中断、恢复和配置变动；不同配置使用不同运行标识。
5. 从完整运行产物中导出小型指标摘要和精选图表到 `results/`，补充分析与失败记录。
6. 检查待提交文件，确认没有本机记录、凭据、数据集或大模型产物后，再按当次任务要求提交或推送。

提交前检查 `git status --short` 和 `git diff`，按明确文件路径暂存，再检查 `git diff --cached`。`.gitignore` 不能保护已经被跟踪或被强制加入的文件；不要强制加入本机说明或凭据。相关规则见 [GitHub 忽略文件说明](https://docs.github.com/en/get-started/git-basics/ignoring-files)。

仓库初始化、提交和推送是独立步骤。是否提交或推送以当前任务的明确要求为准，不把初始化误记为已发布。
