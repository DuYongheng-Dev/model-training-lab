# 阶段 6：延长训练预算

用户提供的[后续建议原文](followup-plan-original.md)已原样归档，设计可执行。本阶段只执行其中的第六阶段；第七阶段的官方 test 和误差分析仍是后续计划。

## 问题与固定条件

从阶段 5 第 20 轮 `last.pt` 继续训练至**总计 50 轮**，新增 30 轮。保持模型、数据划分、seed=42、batch=128、FP32、worker=0、AdamW lr=3e-4、weight_decay=0.01 不变；无增强、dropout 或 scheduler。配置见 [06-budget.json](../configs/06-budget.json)。不因中途验证波动提前改变预算或学习率。

## 指标与判读

- 保留训练时逐 batch 统计的 online train loss / accuracy。
- 新增轮末固定模型、eval 模式遍历 45,000 张训练图的 `train_eval` loss / accuracy。
- 每轮验证 5,000 张 validation，仍按最低 val_loss 选择 epoch 1–50 中的 best，平局保留较早轮。
- 对第 20 轮模型补测 train_eval 基线；第 1–19 轮没有该指标，不伪造历史值。
- 对比第 20、30、40、50 轮及全程 best，结合连续若干轮曲线区分：两者改善、验证平台、训练改善而验证恶化。不凭单轮波动判定收敛，不推断其他训练配方的准确率上限。

## 恢复与资源检查

用户此前已更改设备指定，本阶段继承当前本机选择；具体设备只保存在本机记录。旧运行与新运行之间有物理 GPU 变化，不能称为严格的同设备单变量对照，也不声称跨设备逐位一致。

保留阶段 5 入口与 checkpoint 原件；新增入口只允许从完整阶段 5 的 epoch 20 迁移，明确允许预算、阶段标识和 GPU 变化，校验其他训练配置、模型、数据、依赖与原训练代码哈希一致。继续恢复参数、AdamW 动量及计数、进度、Python / NumPy / CPU / CUDA / DataLoader 随机状态。后续阶段 6 内恢复要求完整身份一致。

迁移后先复核第 20 轮模型和历史 best 的验证指标；预定容差为平均 loss 绝对差 ≤1e-5，正确分类数量相同。额外 train_eval 使用独立顺序 DataLoader，观察前后保存和恢复随机状态，并检查权重和优化器不变，防止监测改变训练轨迹。

先运行有针对性的恢复与观察检查，再试跑第 21 轮。通过后从该轮完整状态续至第 50 轮，第 21 轮计入主轨迹。运行前检查已指定 GPU 的进程与显存、主机可用内存和 SSD 空间。环境、完整日志、源码快照及每轮检查点均存入外部 `LAB_ROOT`；仓库只收录精选结果。所有结果在实测后填写。
