## 2. 从原图到一个 batch

| 对象 | 形状 / 类型 | 如何理解 |
| --- | --- | --- |
| 官方数据中的一张图 | `[32,32,3]`，uint8 | 高、宽、RGB 三个通道；像素为 0–255 的整数 |
| `dataset[i][0]` | `[3,32,32]`，float32 | `ToTensor()` 把通道移到前面，将像素除以 255 |
| `dataset[i][1]` | Python `int` | 一个类别编号，例如 3 表示 cat |
| `images` | `[128,3,32,32]`，float32 | 128 张图沿新增的 batch 维度堆叠 |
| `labels` | `[128]`，int64 | 每张图对应一个类别编号，顺序与 images 一致 |

例如 `images[7]` 和 `labels[7]` 是同一个样本的图像与标签；`images[7,0]` 是该图片的红色通道。batch 不是把 128 张图拼成一张大图，而是给张量增加一个维度。

当前只用 `ToTensor()`，没有增强或标准化，方便直接画图。后续如加入标准化，展示图片时要做相应还原。

## 3. Dataset 与 DataLoader 的分工

```python
image, label = dataset[i]
images, labels = next(iter(train_loader))
```

- Dataset 定义“第 i 个样本是什么”，将图像和标签配成一对。
- `Subset` 指定从官方训练集取哪些索引，形成训练子集。
- DataLoader 决定取样顺序和 batch 大小，并把样本堆叠起来。`shuffle=True` 打乱样本顺序，但不会打乱图像与自身标签的对应关系。
- `iter(train_loader)` 创建一次遍历；`next(...)` 只取下一批。取一批不等于跑完一个 epoch。

本配置下，45,000 张训练图按 batch=128 遍历，`len(train_loader)` 实测为 352；由样本数计算最后一批是 72 张，因为 `drop_last=False`。本阶段仅观察首批，没有遍历整个 epoch。验证集的 5,000 张来自同一官方训练集中的其他索引；官方测试集不参与这些步骤。

## 4. 为什么保存划分索引

seed=42 用于固定随机过程。我们把具体的 45,000/5,000 索引也保存下来，并记录哈希，这样后面的模型和参数实验能够使用同一份划分。每个类别有 4,500 张训练图和 500 张验证图。

同种子首批一致的检查会重新创建 DataLoader 及其 generator。它不意味着一个已经迭代过的 generator 会自动回到开始；generator 的状态会随着取样推进，这也是后续恢复训练需要保存的状态之一。
