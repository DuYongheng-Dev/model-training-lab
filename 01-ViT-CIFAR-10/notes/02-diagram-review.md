核对对象：用户提供的“初始化 Transformer 结构”图，对照当前 [model.py](../src/model.py)。整体数据流、配置和 **809,354** 个参数的总数正确。

## 两处需要修正

1. MLP 第一层 Linear 应写成 **`128 × 512 + 512 = 66,048`**；图中偏置数量写成了 `612`，小计写成了 `65,048`，这一行需一起修正。第二层 `512 × 128 + 128 = 65,664` 正确，两层合计 **131,712**；图中的 MLP 总数、block 总数和模型总数已经是正确值。
2. 在四个 Transformer block 与“取 CLS”之间补上 **最终 LayerNorm**。它不改变 `[B,65,128]` 的形状；参数表中已经正确计入 `128 + 128 = 256`。

完整主线：

```text
图片 [B,3,32,32]
→ patch 投影 [B,128,8,8]
→ 展开 [B,64,128]
→ 拼接 CLS [B,65,128]
→ 加位置编码 [B,65,128]
→ 4 个独立 Transformer block [B,65,128]
→ 最终 LayerNorm [B,65,128]
→ 取 CLS [B,128]
→ Linear(128,10) → logits [B,10]
```

## 参数复核

| 部分 | 参数个数 |
| --- | ---: |
| patch 投影：`128 × (3×4×4) + 128` | 6,272 |
| CLS | 128 |
| 位置编码：`65×128` | 8,320 |
| 单个 block 的注意力投影 | 66,048 |
| 单个 block 的 MLP | 131,712 |
| 单个 block 的两个 LayerNorm | 512 |
| 四个 block：`4 × 198,272` | 793,088 |
| 最终 LayerNorm | 256 |
| 分类头：`128×10+10` | 1,290 |
| **合计（block 内部明细不重复相加）** | **809,354** |

注意力头数 4 表示把 128 维分成每头 32 维，不应再把 QKV 参数乘以 4。patch 投影在 64 个位置共享，也不把参数数目乘以 64。batch size 只改变一次处理多少张图，不改变模型参数量；中间张量、计算量和显存需求会变化。

这里的 Tiny ViT 是本实验选定的小规模 ViT 配置。“最小”可以表达教学简化，但不表示这是数学上最小或唯一的 ViT 配置。

## 前一轮回答补充

- patch=8 时共有 16 个图像 token，加 CLS 后为 17：理解正确。
- 位置参数实际是 `[1,65,128]`，输入是 `[B,65,128]`。末两维刻意匹配以便逐元素相加；第一维 1 广播到每张图，因此 batch size 改变时不需创建新的位置参数。若改变分辨率或 patch 大小，token 数改变，当前实现需要相应重建位置参数，不能直接套用原来的 65 个位置。
- `labels=[9,3]` 表示第一张图的真实类别编号是 9，第二张是 3；不是模型生成的两个分类分数。`logits[0]` 的 10 个数才是模型对第一张图各类别的评分。你对 logit 不是概率的理解正确。
